## Implementation notes
- No `check` script in apps/web/package.json despite [AGENTS.md](http://AGENTS.md) referencing pnpm check; preparation: run pnpm lint + tsc, or ask owner.
- Use @aspiralabs/ui component docs (get_component for a select/SegmentedControl) for sort control and IntersectionObserver sentinel placement before markup.
- Cursor: base64url JSON with version, sort values, id plus hash of q/sort/filters/mode/viewerId; mismatch -\> 400.
- Fixing RecipeCard nested save control inside Link affects 7 callers (marketing pass user=undefined); regression test anonymous.
- The plan uses supplied source/research evidence and claims no additional reads, modifications or executed tests.
- New-file paths are proposed targets, not claims those files already exist; cited neighbors establish conventions.
- Cursors are continuation state, not authorization. Strict context validation and fresh server predicates remain necessary.
- Use relevance id DESC as its deterministic tie-break; the spec fixes the other directions.
- Compare cursor values directly rather than requiring the source row to remain visible, so revocation does not prevent paging eligible remaining rows.
- Mutable rating/time/cookbook ordering may change positions; clients dedupe ids. Newest must use recipe creation, not publication time.
- No schema migration is proposed. Do not expand into new filters, unrelated security fixes or repository-wide configuration/cache migration.
- Detect external access changes through wired mutation, focus/reconnect and server-response revalidation; no new real-time service is implied.
