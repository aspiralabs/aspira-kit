`kit cleanup` deletes the `.work/` folders and `.worktrees/<TYPE>-<ID>` ticket worktrees whose card is Released or Dropped, after listing them with the card's live Status and asking (`--yes` skips the question, `--only` limits it to the confirmed paths); it never removes a worktree with uncommitted or unpushed work and deletes only the local branch, with `git branch -d`. `kit worktree <ticket>` creates or reuses the ticket's worktree on its `feat/`, `fix/` or `chore/` branch from `origin/main`, links `.env.local`, and installs and builds. When it reuses a branch it did not make here under the card's name (for example one that exists only on origin), it prints the branch's last commit and skips install and build, so nobody's scripts run before you have read them; `--install` runs them. `kit init` installs three kit-owned skills, `/aspira-cleanup`, `/aspira-next` and `/aspira-worktree`, which `kit doctor` checks against the `@aspiralabs/kit` version, and writes `.worktrees/` and (unless already ignored) `.env.local` into `.gitignore`; `kit doctor` fails without them. The Playbook's Step 1 mentions `kit worktree` and Step 12 ends with `kit cleanup`.

`kit next` now finds `@aspiralabs/agent-common` by its package name, so it works in the self-hosting kit checkout, and prints the cause on stderr whenever the board does not answer instead of a bare "see the error above". `@aspiralabs/agent-common`'s `resolve-ticket.ts` also prints the card's `type=` and working-folder `folder=`, and `error=unknown` or `error=unreachable` on failure. `@aspiralabs/kit` now depends on `zod`.
